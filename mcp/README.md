# mcp/ — the Bot Poker MCP server

An MCP server wrapping the Bot Poker table's HTTP API, so an agent can play through its tools: all but `docs` wrap the table; `docs` returns the docs. The hosted connector runs this same code; you don't need to run it yourself to play (see the [README](../README.md)).

Two transports, one codebase: **stdio** (default, for Claude Desktop and local use) and **Streamable HTTP** (`OBGL_TRANSPORT=http`, what [deploy/cloudrun/](../deploy/cloudrun/) serves to claude.ai custom connectors). See `server.py`'s module docstring for how the two share one `build_server()` — the only real difference is how a `PokerSession` gets scoped to a caller.

## Files

- `table_client.py` — thin HTTP client for the table API. No game logic.
- `session.py` — hand/step bookkeeping (`PokerSession`), staleness and validation errors, `compute_score()`. No MCP or network framing; the unit tests exercise it directly.
- `server.py` — the MCP server: eight tools (`docs`, `rules`, `table`, `state`, `act`, `next_hand`, `score`, `table_results`), two resources (`obgl://docs/AGENTS.md`, `obgl://docs/WAYS-TO-PLAY.md`), over either transport; over HTTP also the docs as web pages (`/`, `/docs/`, `/docs/*.md`, and the Privacy Policy and Terms at `/docs/privacy`, `/docs/terms`). With sign-in, the browser table at `/table`, and every tool plays the account's one table.
- `oauth/` — OAuth on the HTTP connector (on when `OBGL_PUBLIC_URL` is set): this server is the authorization server, using the mcp SDK's routes (metadata, dynamic client registration, `/authorize`, `/token`, `/revoke`) around our provider. `/authorize` shows a sign-in page (Continue with GitHub, Continue with Google); we mint our own tokens. Start at `oauth/__init__.py` (config, env names), then `provider.py`, `web.py`, `idp.py`, `store.py`.
- `tables.py` — each account's one table (its newest table session; made on first use, replaced by a reset), and who is at it (the last move, who was seen, who moved in each recent hand: in memory only). Whoever moves first on a decision makes it. Records live in the OAuth store.
- `programs.py` — program tokens, one per account: made, regenerated and revoked on the table page, kept as sha256, accepted only by the table's API and only on the owner's table, 20 requests a second, lookups cached a minute.
- `table_web.py` — the browser table at `/table` (sign-in, the account's table, the Programs box): the Go table's own page, proxied, and the JSON API it and programs call. The module docstring lists the routes.
- `bots.py`, `bot_web.py` — submitted bots: a wasm module and its data files, declared by size and sha256, uploaded, queued to be checked (`finalize.py`) and kept as numbered versions; one an hour per account; the routes on the table's API under `/table/api/bots`
- `ranked.py` — ranked tables: every finalized bot version queues one (auth store: the table, the queue, the account's list); a runner plays the queue one table at a time with `rankedtable` (in the server with `OBGL_RANKED_RUNNER=in-process`, or `python ranked.py run` as the Cloud Run job: `deploy/cloudrun/RANKED-TABLES.md`) and files each record where the table serves results (`OBGL_RECORDS`); `GET /table/api/tables` lists them
- `finalize.py` — checking submissions: a finalize queues one; the runner (in the server, or `python finalize.py run` as the Cloud Run job: `deploy/cloudrun/BOT-STORAGE.md`) reads every file back, runs `botcheck`, and files the version and queues its ranked table, or rejects it
- `jobs.py` — the Cloud Run jobs the server starts (`OBGL_FINALIZE_JOB`, `OBGL_RANKED_JOB`; the Run Admin API's `jobs.run`) when it queues work no runner holds, and what their runners share
- `badges.py` — the badges a ranked table earns its coach (top 5, top 3, gold for a win), awarded once per table by the runner, with points summed per season (`OBGL_SEASON`, `OBGL_BADGE_POINTS`); `GET /table/api/badges` shows them
- `bot_files.py`, `bot_files_gcs.py` — where submitted bots' files live: a local directory that serves the upload sessions itself, or Cloud Storage (`deploy/cloudrun/BOT-STORAGE.md`)
- `pages.py` — the HTML page shell the landing, docs index and legal pages share, and the links to the legal pages. The sign-in page has its own self-contained look in `oauth/web.py`.
- `markdown_lite.py` — the small markdown renderer behind `/docs/privacy` and `/docs/terms` (no markdown package; it refuses markdown it does not handle).
- `oauth_testing.py` — a scripted OAuth client (register, PKCE, the sign-in buttons, `/token`), a browser signing in at `/table`, and `FakeIdP` (a fake GitHub/Google), for the tests and `deploy/local/smoke.py`. Not shipped in the image.
- `test_session.py` — unit tests (no network).
- `conftest.py` — the `run_server` fixture (starts `server.py` over HTTP on a free or given port), `serve_asgi` (an in-process app on a real socket), and `site` (the server in-process with a fake GitHub, so a browser and an agent can sign in as the same account).
- `test_oauth_provider.py` — the OAuth server in-process over ASGI: register, authorize, code, token, refresh, revoke, PKCE, single-use codes, resource binding, the sign-in page (what it offers, that guest is gone and retired guest tokens stop working), expiry, the stores, env config. Our app is in-process; the fake GitHub is on a local socket.
- `test_oauth_upstream.py` — GitHub and Google sign-in against a fake upstream IdP on a local socket.
- `test_tables.py` — `tables.py` in-process: one table per account (made once, kept across a restart, an old account's newest session, a lost one replaced), reset, naming only the current table, presence with no store writes, the account's table read from the store once, the finished-hand cache.
- `test_programs.py` — `programs.py` in-process: shown once, hashed at rest, read back without the token, last use written at most once a minute, revoke, one per account and regenerate, the rate limit before any read, cached lookups.
- `test_bots.py` — `bots.py` on a local store, in-process: a version from a submission, files kept by sha256 and not uploaded twice, wrong bytes, missing files, not a module, the caps, the hourly limit, resuming and replacing an open submission, expiry, the local upload sessions
- `test_finalize.py` — checking apart from the request: a finalize queued, the version and its table filed or the submission rejected, the queue drained in order, a stopped runner's submission checked again, the job started on queueing and on a later ask, the job's command
- `test_jobs.py` — starting the ranked job when a table is queued (a fake starter), and the Run Admin API call (a fake session)
- `test_bot_submit.py` — the submission routes over real HTTP with the real `botcheck`, and the SDK's `bot submit` and `bot list` against them. Skips without `go`
- `test_ranked.py` — ranked tables with the real `rankedtable`, the real Go table (`-records`) and tiny tables: the SDK submits, the server queues and plays, the list links the result, the page and `table_results` (no id) read it; a bot that loops forever still gets a table that shows its faults; a runner stopped mid-queue (or crashed, or failing itself) loses no table, on the file store. Skips without `go`
- `test_badges.py` — the badge rules (places 1, 3, 5, 6; small tables), once per table, points per season, the runner's award (a fake `rankedtable`: no `go` needed), `GET /table/api/badges`, the tables list, `table_results`'s last line, the page's badges line
- `test_image.py` — the Dockerfile copies every mcp module the server and the ranked-table job import (it names them one by one)
- `test_bot_files_gcs.py` — `bot_files_gcs.py` against a stand-in for the Cloud Storage client
- `test_table_web.py` — the browser table over real HTTP, signed in through the fake GitHub: sign-in, one table for the browser and every agent connection, whoever moves first (the agent told so in words), settings and reset the page's only, each table its owner's only, a program token playing the owner's table and nothing else (not `/mcp`, not the page-only routes; revoked at once), its rate limit, one token an account (a second refused; regenerate: the old refused, the new works; revoke then make), a page shown the end of a hand it polled past. Each runs on the memory store, and on Firestore when an emulator is up (`FIRESTORE_EMULATOR_HOST`). Table-touching tests skip without a table.
- `test_table_results.py` — `table_results()` and `/table/results/<id>` in-process against a fake Go table answering with the Go report's own text (the golden file `poker/engine/league/testdata/table-p8.txt`): the text read aloud, an unknown table's error, and with sign-in the page link and the page open without sign-in.
- `test_table_browser.py` + `table_browser_check.py` (marked `browser`; `-m "not browser"` leaves them out) — the page in headless Chrome: playing, the dock and its sizes, the agent's and a program's moves shown as they land with who made them, the Programs box (make, copy, regenerate, revoke), the pause when idle or hidden, an old watch link landing on the table; and watching your bot: the SDK's example plays 5 hands with a token and the page replays every one, every move, then Jump to latest skips a second run of 5. The long version (50 hands, then 40 jumped) is opt in: `OBGL_MANY_HANDS=1 python -m pytest mcp/test_table_browser.py -k many_hands` (with `OBGL_BROWSER_PYTHON`, `OBGL_TABLE_URL` as below) (Playwright, in its own python: set `OBGL_BROWSER_PYTHON`, and `OBGL_BROWSER_CHROME` for the Chrome binary). Skips itself unless set. The page comes from the table binary, so point `OBGL_TABLE_URL` at a table built from this tree.
- `test_oauth_http.py` — our server (in-process on a socket) with OAuth on and a fake GitHub, over real HTTP: 401 without a token, GitHub sign-in then tools (and, if the table is up, one hand, and each account's table recorded durably), the SDK's own OAuth client discovering everything from the 401, MCP sessions bound to their account, tokens surviving a restart. Each test runs with the file store, and with Firestore when an emulator is up (`FIRESTORE_EMULATOR_HOST`).
- `test_oauth_store.py` — one contract for every store backend (memory, file, Firestore): round trips, copies, single-use `take` under 20 concurrent takers, `update` under 20 concurrent writers, reopen; plus Firestore's layout, TTL field and expiry. The Firestore cases need the emulator (the file's docstring says how to start one) and skip without it.
- `test_docs.py` — the `/docs/*` pages (exact file bytes, content types, the rendered legal pages and that they carry no drafting markers) and the `docs()` tool. Needs no table.
- `test_delete_account.py` — `deploy/cloudrun/delete_account.py` against the Firestore emulator: dry run lists, `--delete` removes one account's records and no one else's. Skips without the emulator.
- `test_markdown_lite.py` — the legal-page renderer, no server.
- `test_e2e.py` — runs `server.py` over stdio with the MCP Python client, plays 3 hands, checks `score()` against the table's own history. Skips itself if no table is reachable.
- `test_e2e_http.py` — the same shape, over real Streamable HTTP (`OBGL_TRANSPORT=http`), plus a second test that two concurrent connections don't share poker state — the actual point of per-connection session scoping. Skips itself if no table is reachable.
- `test_examples.py` — the onboarding examples in `examples/` (Python, JavaScript, TypeScript) each playing three hands of the account's table with a program token. JavaScript and TypeScript skip without node (TypeScript: 22.18+).
- `test_sdk_table.py` — the Go SDK's table client (`go run ./sdk/example -table`) playing the account's table with a program token made by the page. Skips without `go` or a table.
- `test_smoke.py` — `deploy/local/smoke.py --stay-on-base` against a server whose OAuth issuer is another origin: the table check's sign-in stays on the given URL. Skips without a table.

## Running it locally

Needs Python 3.12 with `pip install -r mcp/requirements.txt` (a hash-locked file compiled from `requirements.in`: `mcp`, `google-cloud-firestore`) and a reachable table; the tests also need `pytest` and `pytest-asyncio`.

```sh
python -m pytest mcp/ -q                            # unit tests + both e2e suites (table-touching tests skip without a table)
python mcp/server.py                                # stdio, for a local MCP client
OBGL_TRANSPORT=http PORT=8080 python mcp/server.py   # Streamable HTTP at :8080/mcp
OBGL_TRANSPORT=http PORT=8080 OBGL_PUBLIC_URL=http://127.0.0.1:8080 OBGL_AUTH_STORE=memory python mcp/server.py   # same, OAuth on (no IdP configured, so no way to sign in); without OBGL_AUTH_STORE it wants Firestore
```

`OBGL_TABLE_URL` sets the table's base URL (default `http://localhost:9777/poker/`), for the server and the tests alike. `HOST`/`PORT` only matter for the HTTP transport (defaults `0.0.0.0`/`8080`).
